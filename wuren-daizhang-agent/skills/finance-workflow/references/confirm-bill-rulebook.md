# 确认单规则底稿

最后整理时间：`2026-06-04`

这份底稿用于给 `无人代账` 提供稳定的确认单判断与填单规则。

## 1. 已验证的页面与入口

### 银企直连明细查询

- 页面：`/transaction/transaction-record`
- 列表接口：`POST /api/pay/transactionRecord/queryPage`
- 上游确认入口：`POST /api/pay/transactionRecord/confirmData`

**筛选字段语义**

- 公司：`merchantNos` / 页面显示公司名称
- 流水号：`orderNo`
- 银行账号：`bankAccountNo`
- 交易金额：`transAmount`
- 交易时间：`orderDate` -> `startOrderDate` / `endOrderDate`
- 业务类型：`businessType`

**记录里必须重点读取的字段**

- 订单金额：`amount`
- 业务类型：`businessType`
- 交易时间：`transTime` 或 `accountDate`
- 对方银行账号：`outBankAccountNo`
- 对方银行户名：`outBankAccountName`
- 摘要：`abstracts`
- 用途：`purpose`
- 流水号：`orderNo`

### 进项发票 - 发票获取

- 页面：`/invoice/input-invoice`
- 查询接口：`POST /api/invoice/inputinvoice/queryInputInvoicePage`
- UAT 现状：无日期筛选时可返回全量列表；若带 `bizDateStart` / `bizDateEnd` / `bizDate` 返回 `缺少请求体`，应退回“无筛选全量 + 本地按 bizDate 过滤”

**筛选字段语义**

- 发票种类：`invoiceClass`
- 发票号码：`invoiceNumber`
- 发票代码：`invoiceCode`
- 购方名称：`buyerName`
- 购方税号：`buyerTaxNo`
- 销方名称：`sellerName`
- 销方税号：`sellerTaxNo`
- 开票日期：`bizDate` -> `bizDateStart` / `bizDateEnd`

**展开详情时必须拿到的语义字段**

- 发票种类
- 发票号码
- 发票代码
- 开票日期
- 不含税金额 / 开票金额：`amountWithoutTax`
- 税率：`taxRate`
- 税额：`taxAmount`
- 价税合计 / 发票总额：`totalAmount`
- 购方名称 / 税号
- 销方名称 / 税号
- 发票状态
- 认证日期 / 抵扣月份 / 附件状态（如页面可见）

### 确认单管理

- 页面：`/bill/query/confirmBill`
- 查询接口：`POST /api/bill/order-confirmation/queryOrderConfirmPage`
- 更新接口：`POST /api/bill/order-confirmation/update`
- 提交已有确认单：`POST /api/bill/order-confirmation/submitExpenses`

注意：确认单管理页当前不是“任意总结单上传入口”，更像“已有确认单记录的查询 / 修改 / 提交页”。

## 2. 标准化规则

### 业务方向标准化

- `businessType = SUB` 或页面语义为“减少”时：统一记为 `减少(贷)`
- `businessType = ADD` 或页面语义为“增加”时：统一记为 `增加(借)`
- 若系统返回其他原始值，先保留原值，并标记 `待核实`

### 对方户名类型判断

- `outBankAccountName` 去掉首尾空格后，字数 `< 4`：定义为 `个人`
- `outBankAccountName` 去掉首尾空格后，字数 `>= 4`：定义为 `公司`

### 金额规则

- 当前阶段只允许**精确金额匹配**
- 金额匹配优先使用发票**价税合计** `totalAmount`
- 不允许把税额单独拿来和银行金额匹配
- 不允许做拆分、多张合并、部分核销、模糊金额匹配
- 这些复杂金额逻辑留待后续版本

## 3. 当前版本匹配逻辑（V1）

### 银企直连减少项 -> 进项发票

当银企直连记录满足以下条件时，才进入自动匹配候选：

1. 业务方向是 `减少(贷)`
2. 对方户名类型判定为 `公司`
3. 能拿到进项发票“发票获取”详情

**匹配条件**

- 银企直连 `outBankAccountName` 与进项发票 `sellerName` 完全一致
- 银企直连 `amount` 与进项发票 `totalAmount` 完全一致

满足后，才认为是“可生成确认单的候选匹配”。

### 当前不自动生成确认单的场景

- 对方户名被判定为 `个人`
- `sellerName` 与 `outBankAccountName` 不一致
- 金额不一致
- 进项发票详情拿不全
- 借贷分录无法平衡
- 需要模糊匹配、拆分匹配、多票合一、部分核销

以上场景先进入 `异常池候选 / 异常输出`，不要强行生成确认单。

### 当前保留待后续处理的方向

- 银企直连 `增加(借)` 与销项发票 / 收款确认逻辑
- 员工类付款与员工报销的自动细分
- 多金额、多单据的复杂配对

## 4. 确认单填写规则

确认单行项目里至少要关注：

- 摘要
- 科目方向
- 科目
- 金额

### 摘要来源

摘要优先按以下顺序取值：

1. 银企直连 `abstracts`
2. 银企直连 `purpose`
3. 银企直连 `bankRemarks`
4. 银企直连 `orderNo`

### 借贷平衡

- 确认单必须同时存在借方与贷方
- 借方金额合计必须等于贷方金额合计
- 任何不平衡情况都不得进入“待确认”
- 不平衡一律进入 `异常池`

### 状态规则

- `INIT(0)`：草稿
- `CONFIRMING(1)`：待确认
- `CONFIRMED(2)`：已确认
- `POSTED(3)`：已过账
- `EXCEPTION(4)`：异常池

`无人代账` 当前只应主动产出两种业务结果：

- `CONFIRMING`
- `EXCEPTION`

`CONFIRMED` 与 `POSTED` 需要人工介入后完成，不要由机器人擅自推进。

## 5. 页面已验证的确认单类型

当前确认单管理页已看到的类型：

- `1001`：付款发票确认单
- `1002`：付款发票确认单（员工）
- `1003`：预付账款确认单
- `1004`：应付账款确认单
- `1005`：预付账款核销单
- `1006`：应付账款核销单
- `2001`：收款发票确认单
- `2002`：预收账款确认单
- `2003`：应收账款确认单
- `2004`：预收账款核销单
- `2005`：应收账款核销单

如果会计规则能对应上，但页面没有明确可选的确认单类型，不要擅自伪造类型值；应先输出 `待核实` 或 `异常池`。

## 6. 从《规则确认单匹配1.docx》抽取的会计规则

以下规则用于“科目方向 / 科目 / 金额”的选择依据。

### 收款发票确认单

- 数据条件：有银行收款回单，有销项发票，不关联原单
- 借方：`1002.01` 银行存款-银行 = `totalAmount`
- 贷方：`6001.01` 主营业务收入-服务费 = `amountWithoutTax`
- 贷方：`2221.01.01` 应交税费-应交增值税-销项税额 = `taxAmount`

### 应收账款确认单

- 数据条件：无银行回单，必须有销项发票，不关联原单
- 借方：`1122.01` 应收账款-公司 = `totalAmount`
- 贷方：`6001.01` 主营业务收入-服务费 = `amountWithoutTax`
- 贷方：`2221.01.01` 应交税费-应交增值税-销项税额 = `taxAmount`

### 预付账款确认单

- 数据条件：必须有银行回单，无需发票，不关联原单
- 借方：`1123` 预付账款-公司 = `totalAmount`
- 贷方：`1002.01` 银行存款-银行 = `totalAmount`

### 预收账款确认单

- 数据条件：必须有银行回单，无需发票，不关联原单
- 借方：`1002.01` 银行存款-银行 = `totalAmount`
- 贷方：`2203.01` 预收账款-公司 = `totalAmount`

### 支出发票确认单（对公）

- 数据条件：必须有银行回单，必须有进项发票，不关联原单
- 借方：业务科目（管理费用 / 成本 / 资产等） = `amountWithoutTax`
- 借方：`2221.01.02` 应交税费-应交增值税-进项税额 = `taxAmount`（专票）
- 贷方：`1002` 银行存款 = `totalAmount`

### 支出发票确认单（员工报销）

- 数据条件：必须有银行回单，必须有发票，不关联原单
- 借方：`6602 / 6601` 管理费用 / 销售费用 = `amountWithoutTax`（专票）或 `totalAmount`（普票）
- 借方：`2221.01.02` 应交税费-应交增值税-进项税额 = `taxAmount`（专票）
- 贷方：`1002` 银行存款 = `totalAmount`

### 应付账款确认单

- 数据条件：无银行回单，必须有进项发票，不关联原单
- 借方：业务科目（成本 / 费用 / 资产等） = `amountWithoutTax`
- 借方：`2221.01.02` 应交税费-应交增值税-进项税额 = `taxAmount`（专票）
- 贷方：`2202` 应付账款 = `totalAmount`

### 固定资产确认单

- 数据条件：必须有银行付款流水，必须有进项发票，不关联原单
- 借方：`1601` 固定资产（或明细） = `amountWithoutTax`
- 借方：`2221.01.02` 应交税费-应交增值税-进项税额 = `taxAmount`（专票）
- 贷方：`1002` 银行存款 = `totalAmount`

### 银行手续费确认单

- 数据条件：必须有银行付款流水，无需发票
- 借方：`6603` 财务费用-手续费 = `totalAmount`
- 贷方：`1002` 银行存款 = `totalAmount`

### 利息收入确认单

- 数据条件：必须有银行收款流水，无需发票
- 借方：`1002` 银行存款 = `totalAmount`
- 贷方：`6603` 财务费用-利息收入 = `totalAmount`

### 借款及利息确认单（仅本金）

- 数据条件：必须有银行收款流水，无需发票，附件需要银行回单与借款合同
- 借方：`1002` 银行存款 = `totalAmount`
- 贷方：`2001 / 2501` 短期借款 / 长期借款 = `totalAmount`

## 7. 使用边界

- 这份底稿先作为 `无人代账` 的执行规范，不等同于已经全部做成可一键跑通的脚本
- 当前页面 / 接口层已确认的能力，不代表每个确认单类型都已经完成自动填单
- 若页面字段、确认单类型、会计规则三者之间出现冲突，先输出 `待核实`，不要擅自落单
